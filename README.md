# 高校生クイズ ○×過去問 学習Webアプリ

GitHub Pagesだけで動作する、iPhone Safari向けの○×クイズ学習アプリです。サーバー、データベース、外部API、ビルド環境は不要です。

## ファイル構成

- `index.html` 画面
- `style.css` iPhone向けUI
- `app.js` CSV読込・出題・履歴保存・CSVバックアップ/復元
- `高校生クイズ○×クイズ過去問.csv` 問題データ（2935問）
- `manifest.json` PWA設定
- `service-worker.js` オフラインキャッシュ
- `icons/` ホーム画面用アイコン

## GitHubリポジトリへの配置方法

1. GitHubで新しいリポジトリを作成します。
2. このフォルダ内のファイルと `icons` フォルダを、リポジトリのルートにそのままアップロードします。
3. CSVファイル名は `高校生クイズ○×クイズ過去問.csv` のままにしてください。名前を変える場合は `app.js` と `service-worker.js` のCSVファイル名も同じ名前へ変更してください。

## GitHub Pagesの有効化方法

1. GitHubのリポジトリで `Settings` を開きます。
2. 左側の `Pages` を開きます。
3. `Build and deployment` の Source を `Deploy from a branch` にします。
4. Branch を `main`、フォルダを `/(root)` にして保存します。
5. 表示されたGitHub PagesのURLをiPhone Safariで開きます。

## CSVを差し替える方法

同じ6列を持つCSVへ差し替えられます。

`大会, 予選, 問題番号, 問題, 正解, 補足`

「正解」は `○` または `×` にしてください。CSVは引用符、引用符内のカンマ、改行に対応しています。問題IDは「大会 + 予選 + 問題番号」で作られるため、同じ問題についてこの3項目を維持すれば既存履歴も維持されます。

CSVを更新した場合、確実に新しいCSVをオフラインキャッシュへ反映させるには `service-worker.js` の `CACHE_NAME` の末尾（例: `v1` → `v2`）を変更してください。

## iPhoneでホーム画面へ追加する方法

1. SafariでGitHub PagesのURLを開きます。
2. Safariの共有ボタンを押します。
3. `ホーム画面に追加` を選びます。
4. 追加したアイコンから起動します。

初回読み込み後は、HTML/CSS/JavaScript/CSVをService Workerへキャッシュするため、可能な範囲でオフライン利用できます。

## 回答履歴の保存場所

回答履歴はSafariの `localStorage` に、キー `highschoolQuizOX.history` で保存します。回答ボタンを押した直後に毎回保存します。保存データには `version: 1` を持たせています。

同じGitHub Pages URLを同じSafariで利用する限り、通常はSafariを閉じたりiPhoneを再起動したりしても残ります。ただし、SafariのWebサイトデータ削除、端末設定、ストレージ管理などでlocalStorageが消える可能性はあるため、重要な履歴はCSVバックアップも使用してください。

## CSVバックアップ

画面右上の `成績` → `成績CSVを保存` を押します。

元の6列の右側に以下を追加したUTF-8 BOM付きCSVを保存します。

`回答回数, 正解数, 不正解数, 正答率, 最終回答日時, 最終回答`

未回答問題は回答回数・正解数・不正解数が0になります。

## CSVから履歴を復元

1. `成績` → `成績CSVを読み込む` を押します。
2. 過去に保存した成績CSVを選びます。
3. 確認ダイアログで承認すると、CSV内の履歴でlocalStorageの履歴を置き換えます。

履歴列のない元の問題CSVを選んだ場合、履歴は変更しません。同じ成績CSVを複数回読み込んでも加算されず、毎回「復元・置換」として扱われます。

## 履歴リセット

`成績` → `全履歴を削除` を押し、確認ダイアログで承認すると全回答履歴を削除します。

## 出題仕様

全問題からランダムに出題します。直近20問の問題IDを別途localStorageに保存し、候補が十分ある限り直近20問を再出題しません。出題選択と履歴保存を分離しているため、将来「未回答優先」「間違えた問題優先」などの方式を追加しやすい構造です。
